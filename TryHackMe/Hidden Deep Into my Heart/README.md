## Methodology

### 1. Reconnaissance

I began by accessing the target web application through Firefox. The initial page consisted of a minimal interface with no apparent navigation links or interactive elements.

To investigate potential client-side clues, I inspected the page using Firefox Developer Tools, examining the HTML structure, available elements, and CSS for hidden content or functionality. No significant findings were identified during this initial inspection.

Given the limited information exposed by the landing page, I shifted to directory and resource enumeration to identify additional application paths.

### 2. Directory Enumeration

I used Dirsearch to enumerate potentially accessible directories and files on the web server.

```bash
dirsearch -u http://10.145.191.2:5000
```

Dirsearch performs HTTP requests against candidate paths using a wordlist to identify resources that may not be linked from the application's interface.

The scan identified `/robots.txt` as an accessible resource of interest.

### 3. Robots.txt Analysis

I navigated to the discovered `/robots.txt` resource and inspected its contents.

The file revealed a disallowed path:

`/cupids_secret_vault`

It also exposed a string that appeared to be a potential password.

Although robots.txt is intended to provide crawling guidance to search engine crawlers, its contents are publicly accessible and can inadvertently disclose sensitive application paths or information.

### 4. Further Enumeration

Using the newly discovered directory as the enumeration starting point, I performed another Dirsearch scan.

```bash
dirsearch -u http://10.145.191.2:5000/cupids_secret_vault
```

This scan identified an additional path:

`/cupids_secret_vault/adminstrator`

Navigating to this endpoint revealed a login interface titled "Cupid's Vault," containing username and password fields.

This discovery established an authentication endpoint and provided a new attack surface for investigation.

### 5. Authentication Testing

Rather than attempting to guess the credentials manually, I chose to use Burp Suite to practice HTTP request interception and authentication testing.

I configured FoxyProxy to route Firefox traffic through Burp Suite and captured the login request generated by the application.

I then forwarded the request to Burp Suite Intruder and configured a payload attack to test potential usernames against the password discovered during reconnaissance.

The resulting responses identified a valid authentication combination.

### 6. Flag Retrieval

Using the discovered credentials, I successfully authenticated to the application and accessed the protected content containing the challenge flag.

This completed the challenge.

## Key Findings

| Finding | Security Impact | Remediation |
|---|---|---|
| Sensitive paths disclosed through robots.txt | Provides attackers with information about potentially sensitive application resources | Avoid listing sensitive paths in publicly accessible robots.txt files |
| Exposed administrative login endpoint | Provides an additional authentication attack surface | Restrict administrative access and implement appropriate authentication controls |
| Weak or discoverable authentication credentials | Allows unauthorized access when credentials can be discovered or guessed | Use strong, unique credentials and appropriate authentication protections |

## Key Takeaways

- Practiced web application reconnaissance and directory enumeration using Dirsearch
- Identified how robots.txt can unintentionally disclose application resources
- Gained experience intercepting and manipulating HTTP requests with Burp Suite
- Practiced authentication testing using Burp Suite Intruder
- Reinforced the importance of investigating unexpected resources rather than relying exclusively on the application's visible interface
